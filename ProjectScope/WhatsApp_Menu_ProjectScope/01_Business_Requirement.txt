1. BUSINESS REQUIREMENT DOCUMENT
Project: WhatsApp Restaurant Menu & Food Ordering AI Agent
Version: Demo v0.1

1.1 PURPOSE
Create a configurable demonstration of a restaurant AI agent that communicates through WhatsApp, understands customer requests, answers restaurant FAQs, checks menu/inventory availability, captures food orders, remembers conversational context, and sends a response back to the customer.

1.2 BUSINESS PROBLEM
Small restaurants commonly receive menu questions, availability questions and orders through WhatsApp. Manual handling creates delays and repetitive work. The target concept is an AI-assisted ordering desk that can operate continuously and use controlled restaurant data.

1.3 BUSINESS OBJECTIVES
- Present available menu items.
- Answer FAQs such as opening hours and delivery availability.
- Understand natural-language order requests.
- Ask for missing order information such as customer name and quantity.
- Validate requested items against availability.
- Save confirmed orders.
- Maintain conversation context.
- Send confirmations/replies through WhatsApp.
- Centralize configuration so a restaurant can change behavior without editing workflow logic.

1.4 DEMO USERS
- Restaurant owner/admin.
- Restaurant staff/configuration user.
- Customer/test user.
- Developer/tester.

1.5 DEMO FUNCTIONAL REQUIREMENTS
BR-01: Admin shall configure restaurant identity.
BR-02: Admin shall configure menu/inventory data.
BR-03: Admin shall configure FAQ data.
BR-04: Admin shall configure AI/agent instructions.
BR-05: Admin shall configure memory behavior.
BR-06: Admin shall configure WhatsApp integration fields.
BR-07: Admin shall configure Google Sheets integration fields.
BR-08: Customer shall be able to ask what food is available.
BR-09: Customer shall be able to ask FAQs.
BR-10: Customer shall be able to place an order conversationally.
BR-11: Agent shall not confirm unavailable items as available.
BR-12: Agent shall request missing mandatory order details.
BR-13: Confirmed order shall be recorded.
BR-14: Agent shall preserve conversational context.
BR-15: Agent shall return a human-readable response.
BR-16: Demo shall expose integration status and validation results.

1.6 BUSINESS RULES
- Only available menu items can be offered as available.
- Out-of-stock items must not be confirmed.
- Customer name, item and quantity are mandatory for a confirmed order unless the configured business rule says otherwise.
- Order timestamp is generated by the workflow.
- AI must use inventory/FAQ tools rather than inventing restaurant facts.
- Restaurant name comes from configuration.
- AI must follow the configured restaurant system message.
- A tool failure must not be represented as successful data retrieval.
- Credentials must never be displayed as plain text after secure storage is implemented.

1.7 SUCCESS CRITERIA
A demo is successful when:
1. Admin can edit configuration.
2. Demo data is loaded.
3. A customer asks for the menu and receives available items.
4. A customer asks a configured FAQ and receives the configured answer.
5. A customer places a valid order and the order is saved.
6. A customer requests an unavailable item and the agent refuses that item and offers alternatives.
7. Conversation memory works.
8. Integration health is visible.
9. The existing n8n instance remains untouched.

1.8 OUT OF SCOPE FOR DEMO
- Production WhatsApp number provisioning.
- Production Meta verification.
- Payment gateway.
- Delivery partner integration.
- POS integration.
- Tax/invoice compliance.
- Multi-restaurant SaaS tenancy.
- Production-grade authentication/authorization.
- High availability.
- Real customer data.
